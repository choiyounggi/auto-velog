# blog-loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 세션 중 발현된 ★ BlogWorthy 글감을 세션 종료 시 수확해 스타일 프로필로 집필하고 시크릿 스캔 후 Velog에 자동 발행하는 Claude Code 플러그인.

**Architecture:** dev-loop의 harvest/promote 분리 패턴. SessionStart 훅이 발현 지침 주입 → Stop 훅이 트랜스크립트를 파싱해 큐 적재 + detached headless claude로 draft 스킬 spawn → draft 스킬이 게이트/집필/스캔 후 어댑터 스크립트로 발행.

**Tech Stack:** Node.js ≥18 (ESM .mjs, node:test), Playwright(chromium), bash 훅, Claude Code plugin (hooks.json + skills).

**Spec:** `docs/superpowers/specs/2026-08-14-blog-loop-design.md`

## Global Constraints

- 데이터 디렉토리는 전부 `~/.blog-loop/` (레포에 시크릿·쿠키 절대 커밋 금지)
- 훅은 절대 세션 종료를 블로킹하지 않는다 (백그라운드 + `set +e` + try/catch)
- 범용 기본값 `publish.mode: "approve"` — auto는 사용자가 명시적으로 설정
- 모든 스크립트 ESM `.mjs`, 테스트는 `node --test tests/`
- 블록 구분선은 U+2500(`─`), harvest 정규식과 SessionStart 지침 텍스트는 정확히 동기화

## File Structure

```
blog-loop/
├── .claude-plugin/plugin.json
├── hooks/hooks.json, blog-instruction.sh, harvest-blog.sh

├── tests/{harvest,secret-scan,config}.test.mjs
├── config.example.json
├── package.json / .gitignore / README.md
```

### Task 3: scripts/harvest.mjs (TDD)

**Files:** Create `scripts/harvest.mjs`, `tests/harvest.test.mjs`

**Interfaces — Produces:**
- `extractBlocks(assistantText)` → `[{body, fields:{topic,angle,story,codeRefs,whyWorth}, hash}]`
- `assistantTextFromLine(jsonlLine)` → string
- `harvest(payload, {queueDir})` → 적재된 row 수 (테스트에서 임시 디렉토리 주입)
- CLI(직접 실행 시): stdin에서 Stop 페이로드 읽어 `harvest()` 호출, stdout에 `ADDED:<n>` 출력 (harvest-blog.sh가 spawn 여부 판단에 사용)

**동작 (dev-loop harvest.js 이식 + 변경점):**
- 정규식 `/★\s*BlogWorthy\s*─+\s*\n([\s\S]*?)\n\s*─+/g`
- 필수 필드 `topic`, `story` (없으면 드롭); `<...>` 플레이스홀더 잔존 시 드롭; body 30자 미만 드롭
- dedup: 큐 파일 + `.processed.jsonl`의 hash 집합; 세션당 캡 3
- row: `{hash, sessionId, repo, cwd, transcriptPath, topic, angle, story, codeRefs, whyWorth, content, harvestedAt, status:"pending"}`
- transcript 해석: `payload.transcript_path` 우선, 없으면 `~/.claude/projects/<encoded-cwd>/` 최신 .jsonl

- [ ] 테스트: ① 정상 블록 1개 파싱+큐 적재 ② topic 누락 드롭 ③ 플레이스홀더 에코 드롭 ④ 빈 트랜스크립트 → 0 ⑤ 동일 블록 재수확 dedup ⑥ 4개 블록 → 캡 3
- [ ] 실패 확인 → 구현 → 통과 → Commit: `feat: BlogWorthy harvester with dedup and cap`

### Task 4: scripts/secret-scan.mjs (TDD)

**Files:** Create `scripts/secret-scan.mjs`, `tests/secret-scan.test.mjs`

**Interfaces — Produces:**
- `scanText(text, extraPatterns = [])` → `[{type, line, masked}]` (masked: 앞 4자만 노출)
- CLI: `node secret-scan.mjs <file>` — config의 `secretScan.denyPatterns` 자동 로드, findings JSON 출력, exit 0 clean / 1 findings / 2 error(파일 없음 등)

**패턴 목록 (type → regex):** aws-key `AKIA[0-9A-Z]{16}`, openai/api-token `sk-[A-Za-z0-9_-]{20,}`, github-token `gh[pousr]_[A-Za-z0-9]{36,}`, slack-token `xox[baprs]-[A-Za-z0-9-]{10,}`, jwt `eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{5,}`, private-key `-----BEGIN [A-Z ]*PRIVATE KEY-----`, private-ip `\b(10\.\d{1,3}|192\.168|172\.(1[6-9]|2\d|3[01]))\.\d{1,3}\.\d{1,3}\b`, email `[\w.+-]+@[\w-]+\.[\w.]+`, assignment `(?:password|passwd|secret|api[_-]?key|token)\s*[=:]\s*['"][^'"\s]{8,}['"]`, custom(denyPatterns 각각).

- [ ] 테스트: ① 클린 텍스트 → [] ② 유형별 탐지(aws/jwt/email/private-ip/assignment 최소 5종) ③ 빈 파일 → exit 0 ④ 파일 없음 → exit 2 ⑤ denyPatterns 커스텀 히트 ⑥ masked에 원문 전체 미노출
- [ ] 실패 확인 → 구현 → 통과 → Commit: `feat: secret scanner (regex pass)`

### Task 5: velog 어댑터 이관

**Files:** Create `scripts/adapters/velog/{check-login,login,publish,save-naver-cookies}.mjs`

**Interfaces — Produces:** (스킬·훅이 호출하는 계약)
- `check-login.mjs` → stdout `STATUS:LOGGED_IN|NOT_LOGGED_IN|NAVER_EXPIRED`
- `login.mjs` → 성공 시 `STATUS:LOGGED_IN`, 실패 exit 1
- `publish.mjs <draft.md> [--private]` → `STATUS:PUBLISHED` + `URL:<url>` / exit 2 로그인 필요 / exit 1 실패. frontmatter(`---` YAML: title, tags) 우선, 없으면 기존 H1/태그줄 파싱. 발행 성공 시 `~/.blog-loop/publish-log.jsonl`에 `{ts,title,url,session,score}` append
- `save-naver-cookies.mjs` → 수동 로그인 (headless:false 고정)

**기존 `~/.claude/scripts/*.mjs`에서 변경:** 쿠키 경로 → `SECRETS_DIR`, 이메일 하드코딩 → `config.velog.email`, headless → `config.browser.headless` (publish/check/login), username fallback 하드코딩 제거 → `config.velog.username`, `is_private: --private 플래그`, 썸네일 인자 유지.

- [ ] 4개 파일 이관 작성 (원본 로직 보존, 위 변경점만 적용)
- [ ] `node --check` 급 구문 검증 + check-login.mjs 실 실행 스모크

### Task 6: hooks

**Files:** Create `hooks/hooks.json`, `hooks/blog-instruction.sh`, `hooks/harvest-blog.sh`

**Interfaces — Consumes:** `scripts/harvest.mjs` CLI의 `ADDED:<n>` 출력.

- hooks.json: SessionStart(matcher "startup") → blog-instruction.sh, Stop → harvest-blog.sh (`${CLAUDE_PLUGIN_ROOT}` 경로)
- blog-instruction.sh: BlogWorthy 발현 지침 heredoc 출력. skip 조건: `BLOG_LOOP_DRAFTING=1`, cwd가 `~/.blog-loop`
- harvest-blog.sh: stdin 1회 읽기 → `stop_hook_active` skip → node harvest.mjs 동기 실행(빠름) → `ADDED:0`이면 종료 → PAUSE/`BLOG_LOOP_AUTODRAFT=0`/rate-limit(30분)/single-flight lock 가드 → `BLOG_LOOP_DRAFTING=1 nohup claude -p "/blog-loop:draft 실행" --permission-mode bypassPermissions > ~/.blog-loop/autodraft.log 2>&1 &` + disown
- [ ] 작성 + `bash -n` 구문 검증 + harvest 경로 수동 스모크 (가짜 페이로드)

### Task 7: skills 4종

**Files:** Create `skills/{setup,draft,publish,flush}/SKILL.md`

각 SKILL.md는 frontmatter(name/description 트리거 키워드 포함) + 단계별 지시. 핵심 내용:
- **setup**: `~/.blog-loop` 디렉토리 생성, config.example 복사 후 email/username 질문-기입, `npm i` + playwright 설치 확인, save-naver-cookies 안내, login 실행, `--private` 테스트 발행, PAUSE/킬스위치 사용법 안내
- **draft**: PAUSE 체크 → 큐 pending row 순회: 트랜스크립트 Read → 게이트 스코어링(스펙 4항목 rubric, frontmatter에 기록) → 스타일 프로필(내장 규칙 명시 + referencePosts 있으면 WebFetch few-shot)로 집필 → draft 저장(frontmatter: score/status/session/tags) → secret-scan CLI 실행, exit 1이면 레드액션 시도 후 재스캔, 불가 시 status:blocked + 알림 → mode=auto && score≥minScore && 일일 상한 미달이면 publish 스킬 절차 실행 → row를 `.processed.jsonl`로 이동 → osascript 알림 + log.jsonl append
- **publish**: PAUSE → dailyCap(오늘자 publish-log 카운트) → check-login → 필요 시 login → publish.mjs 실행 → 실패 시 1회 재시도 → 결과 알림/로그. deferred draft 우선 처리
- **flush**: 큐 잔여 + drafts의 pending/deferred/blocked 일람 → 사용자와 함께 일괄 처리, 여러 세션 글감 묶기 옵션
- [ ] 작성 → Commit: `feat: blog-loop skills (setup/draft/publish/flush)`
